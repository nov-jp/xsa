XSA stands for EXtended Style Attribute, representing a next-level extension of the native style attribute. It is a lightweight, zero-build meta-framework that seamlessly combines HTML's inline style attribute with CSS attribute selectors and custom properties.

Based on standard CSS property names, an XSA Property is a custom property wrapped in double hyphens (--) at the beginning and end, encoding specific media queries and selectors within its XSA Prefix. Together with its corresponding XSA Rule Set,

this paradigm establishes a highly portable styling infrastructure directly within the HTML style attribute, allowing you to elegantly handle complex descendant elements, pseudo-elements, media queries, and pseudo-classes.

The XSA ecosystem encompasses the naming conventions, corresponding rule sets, a modular CSS library, and dynamic generation utility scripts. Explore the comprehensive ecosystem via our GitHub repositories and packages:

  • XSA
  • XSA CSS: A lightweight vanilla CSS library containing predefined XSA rule sets.
  • XSA JS: A client-side utility to dynamically generate rule sets from XSA properties.
  • XSA PostCSS: A build-time toolset to extract and generate XSA rule sets.
  • XSA PHP: A server-side helper class to seamlessly parse XSA properties.

While the example above contrasts XSA with Tailwind CSS, XSA does not explicitly dictate or enforce a utility-first methodology. What kind of structural architectural data you embed within your HTML, and how you choose to operate it, is entirely up to you.
